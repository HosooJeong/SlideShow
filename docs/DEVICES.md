# 연출 장치 카탈로그 (Devices)

> "슬라이드쇼"를 "영상"으로 느끼게 만드는 시각 장치들의 탐색 목록. 각 장치는 **실험실(`/lab`)에서 0.5~1일 스파이크** 후 채택/보류/폐기를 기록한다. 이 문서는 살아있는 문서다.

평가 축

- **감성**: 기념일 영상(따뜻함·마법·영화적)과 맞는가
- **난이도**: 1(하루) ~ 5(2주+)
- **GPU**: 노트북 내장 GPU에서 1080p 60fps 가능한가
- **내보내기**: `render(t)`가 결정적인가. 상태를 가진 시뮬레이션(유체·물리)은 t만으로 재현이 안 되므로 **고정 스텝으로 t=0부터 순차 시뮬**해야 한다. 내보내기는 원래 프레임을 순서대로 그리니 문제없고, 재생 중 시크만 근사치가 된다.

---

## A. 공간·카메라

### A1. 3D 카메라 + 깊이 (three.js) — ★ 채택 예정

- 페이지·사진을 3D 공간의 평면(plane)으로 두고, 원근 카메라가 돌리/팬/틸트. 살짝의 원근감만으로도 "2D 슬라이드"와 "영상"의 차이가 난다.
- 얕은 심도(DOF, bokeh)로 카메라가 바라보는 사진만 선명, 주변은 흐림 → 시선 유도.
- 구현: three.js + `postprocessing` DepthOfFieldEffect. 난이도 2, GPU 중, 내보내기 결정적.
- 신문 무대는 거의 정면 카메라(약한 원근), 스트림 무대는 강한 원근.

### A2. 연속 스트림 (마블 시네마틱 인트로 느낌) — ★ 채택 예정, 2호 무대

- 면 구분 없음. 사진들이 곡선 경로(스플라인) 위에 띄워져 있고 카메라가 그 사이를 계속 날아간다. 지나가는 사진은 기울고 회전하며 스치고, 정면에 오는 사진은 잠깐 멈춰 살아 움직인다.
- 속도 램프(느리게 → 확 빨라짐 → 화이트 플래시 → 다음 구간), 모션 블러, 사진 가장자리 빛 새기.
- 구현: `CatmullRomCurve3`에 슬롯 배치, 카메라는 경로를 따라 lookAt 오프셋으로 진행. 모션 블러는 속도 버퍼 기반 또는 프레임 누적(내보내기용). 난이도 3, GPU 중~상.
- 사진 수가 많을 때(100장+) 신문보다 훨씬 잘 어울린다. 신문 = 정적·서사, 스트림 = 동적·몽타주.

### A3. 2.5D 깊이 시차 사진 (사진 자체가 입체로) — 보류(실험실)

- 사진에서 깊이맵을 추정 → 메시를 깊이로 변위 → 카메라가 살짝 움직이면 인물이 배경에서 떠 보인다. "살아있는 사진"의 최종형.
- 구현: transformers.js/ONNX Runtime Web으로 Depth Anything 소형 모델을 브라우저에서 실행(사진당 1~3초), 깊이 텍스처를 vertex displacement. 난이도 4, 전처리 비용 큼, 렌더는 가벼움.
- 브라우저 전용 원칙과 맞음(모델도 로컬 실행). 가장자리 늘어짐 아티팩트를 inpaint 없이 어떻게 감출지가 관건. v1.1 이후.

### A4. 반사 바닥 / 유리 테이블 — 보류

- 사진이 떠 있는 아래에 흐릿한 반사면. 스트림 무대의 프리미엄 느낌 옵션. drei `MeshReflectorMaterial`. 난이도 1, GPU 중.

## B. 재질·광학

### B1. 리퀴드 글래스 — ★ 채택(제한적)

- 두 가지 쓰임새:
  1. **확대 렌즈**: 신문 위를 유리 돋보기가 지나가며 사진을 굴절·확대. 해리포터 신문에 딱 맞는 "장치"이자 카메라 대신 시선을 이끄는 수단.
  2. **타이틀 카드/UI 오버레이**: 제목·날짜가 반투명 유리 판 위에, 굴절·색수차·가장자리 하이라이트.
- 구현: drei `MeshTransmissionMaterial`(굴절·색수차·두께·거칠기 파라미터). 트랜스미션은 배경을 한 번 더 렌더하므로 비용 큼 → 화면에 유리 1~2개만. 난이도 2, GPU 상.
- 주의: 전면에 깔면 "아이폰 UI"처럼 보이고 종이 무드를 깨움. 포인트로만.

### B2. 필름 룩 (그레인·게이트 위브·라이트 리크·헐레이션) — ★ 채택

- 그레인(시간에 따라 변하는 노이즈), 미세한 프레임 흔들림(gate weave), 가장자리 빛 새기, 밝은 부분 번짐(halation/bloom), 비네트, 레터박스.
- 구현: `postprocessing` 패스 조합 + 커스텀 셰이더 하나. 난이도 1, GPU 저. 모든 무대에 얕게 깔린다.

### B3. 하프톤·오프셋 인쇄 룩 — ★ 채택(신문 무대)

- 사진 위 도트 스크린, CMYK 채널 살짝 어긋남(misregistration), 종이 텍스처 곱하기, 잉크 번짐 가장자리.
- 구현: 커스텀 프래그먼트 셰이더. 난이도 2, GPU 저.

### B4. 폴라로이드 현상 — ★ 채택(쉽고 귀여움)

- 흰 프레임에서 사진이 서서히 떠오름(화학 노이즈 → 색 → 대비). 스크랩북 무대의 기본 등장 방식. 난이도 1.

## C. 번짐·용해·변형

### C1. 잉크/수채 번짐 등장 (bleed reveal) — ★ 채택

- 사진이 종이에 잉크가 스며들듯 나타남. 노이즈 마스크의 임계값을 시간에 따라 낮추고, 경계에 어두운 잉크 테두리 + 블러.
- 구현: 노이즈 텍스처(FBM) + threshold + edge darken 셰이더. 난이도 1~2, 결정적.
- 고급형: 핑퐁 FBO로 확산(diffusion) 시뮬 → 진짜 번지는 느낌. 상태 있음(내보내기 순차 시뮬). 난이도 3.

### C2. 파티클 분해·재조합 — ★ 채택(마법 장치의 핵심)

- 사진이 수만 개 입자로 흩어져 날리다가 다음 사진으로 모인다. 해리포터 무드의 "마법"을 가장 직접적으로 준다.
- 구현: GPU 포인트(instanced), 각 입자에 (uvA, uvB) 두 좌표, 커브 노이즈로 중간 경로, t로 보간. 난이도 3, GPU 중. 결정적으로 설계 가능(입자 경로가 t의 함수).

### C3. 액체/디스플레이스먼트 트랜지션 — ★ 채택

- 두 사진 사이를 왜곡 텍스처로 녹이듯 전환. `gl-transitions` 카탈로그(수십 종, MIT)에서 종이·잉크·물결 계열만 골라 쓴다. 난이도 1.

### C4. 종이 물리 (페이지 컬·접힘) — 채택(신문/앨범 전환)

- 페이지가 원통을 따라 말리며 넘어감. 정점을 원통에 감는 vertex shader. 그림자 포함. 난이도 2~3.

### C5. GPU 유체 시뮬레이션 — 보류(실험실)

- 배경으로 흐르는 잉크/물 유체, 사진이 그 위에 떠 있거나 유체가 사진을 드러냄. Navier-Stokes 핑퐁 FBO. 난이도 4, GPU 상, 상태 있음.
- 임팩트 크지만 무드 통제가 어렵다(쉽게 "테크 데모"처럼 보임). 스트림 무대 오프닝 한 번 정도.

### C6. 모프(사진 A 형태가 B로) — 폐기 후보

- 얼굴 정합 없이는 어색. 스코프 밖.

## D. 빛·입자·분위기

### D1. 볼류메트릭 빛·먼지 — ★ 채택

- 창에서 들어오는 빛줄기(god rays), 공기 중 떠다니는 먼지 보케 스프라이트. 앨범·액자 벽 무대의 공기감.
- 구현: 빌보드 스프라이트 + `postprocessing` GodRays 또는 가짜 빛줄기 평면. 난이도 2.

### D2. 컨페티·꽃잎·풍선 — ★ 채택(테마 파티클)

- 간단한 물리(중력·바람·회전) 인스턴스 메시. 결정적으로 만들려면 시드 + 해석적 궤적(t의 함수)로. 난이도 1~2.
- 3D 풍선(GLTF, 돌잔치)은 보너스.

### D3. 렌즈 플레어·화이트 플래시 컷 — ★ 채택

- 스트림 무대의 구간 전환 = 플래시. 난이도 1.

---

## E. 타이포그래피

### E1. SDF 텍스트 (troika-three-text) — ★ 채택(필수 인프라)

- 3D 공간에서 선명한 한글 텍스트. 신문 헤드라인·기사·날짜 전부 여기로. 난이도 1(라이브러리), 한글 폰트 로딩 크기 주의(서브셋).

### E2. 키네틱 타이포 — 채택

- 글자 단위 낙하·타자기·잉크 번짐 등장, 헤드라인이 카메라 이동과 함께 살짝 3D 회전. 난이도 2.

## F. 오디오 반응

### F1. 비트 동기 — ★ 채택(v1.1)

- 음악 온셋/비트 검출 → 컷·플래시·파티클 버스트가 박자에 맞음. Web Audio 분석을 미리 한 번 돌려 비트 타임스탬프 배열로 저장(결정적). 난이도 2.

### F2. 실시간 스펙트럼 반응 — 폐기 후보

- 클럽 비주얼처럼 보임. 무드에 안 맞음.

## G. 인터랙션 (미리보기 전용, 내보내기엔 없음)

### G1. 마우스 시차 — 채택

- 미리보기 중 마우스 위치로 카메라가 아주 살짝 기울어져 입체감. 난이도 1.

## 실험실(`/lab`) 운영 방식

- 앱 안에 `/lab/:device` 라우트. 장치마다 독립 씬 + `leva` 슬라이더로 파라미터 실시간 조정.
- 스파이크 예산 0.5~1일. 끝나면 이 문서의 해당 항목에 **판정(채택/보류/폐기)·스크린샷·GPU 측정치·남긴 파라미터 기본값**을 기록.
- 채택된 장치는 `features/renderer/devices/`로 이동해 무대 템플릿이 조합해 쓴다. 장치 = 재사용 가능한 컴포넌트/패스 단위.
