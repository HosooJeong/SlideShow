# 연출 장치 카탈로그 (Devices)

> "슬라이드쇼"를 "영상"으로 느끼게 만드는 시각 장치들의 탐색 목록. 각 장치는 **실험실(`/lab`)에서 0.5~1일 스파이크** 후 채택/보류/폐기를 기록한다. 이 문서는 살아있는 문서다.

평가 축

- **감성**: 기념일 영상(따뜻함·마법·영화적)과 맞는가
- **난이도**: 1(하루) ~ 5(2주+)
- **GPU**: 노트북 내장 GPU에서 1080p 60fps 가능한가
- **내보내기**: `render(t)`가 결정적인가. 상태를 가진 시뮬레이션(유체·물리)은 t만으로 재현이 안 되므로 **고정 스텝으로 t=0부터 순차 시뮬**해야 한다. 내보내기는 원래 프레임을 순서대로 그리니 문제없고, 재생 중 시크만 근사치가 된다.

## A. 공간·카메라

### A1. 3D 카메라 + 깊이 (three.js) — ★ 채택 (실험실 구현 2026-09-05)

- **판정**: 채택. `/lab/camera-dof`에 구현. 카메라 포즈는 `sampleCamera(keys, t)` 순수 함수로 t에서 결정되며, 이 코드는 2단계 렌더러가 그대로 쓴다(`features/renderer/camera/cameraPath.ts`).
- **기본값**: fov 38, 전체 보기 z 9.5, 근접 거리 3.2, 머무름 2.2s, 이동 1.4s(inOutCubic), 드리프트 0.15, 핸드헬드 0.012, DOF 초점 범위 0.9 / 보케 4.0.
- **관찰**: 근접 거리 2.4는 사진이 프레임을 넘쳐 테두리와 종이가 안 보임 → 3.2로. DOF `target`을 매 프레임 lookAt 지점으로 갱신하면 초점이 자연스럽게 따라온다. 핸드헬드는 두 주파수 사인 합이면 충분(노이즈 불필요).
- **GPU**: 헤드리스 SwiftShader(소프트웨어)에서 4fps — 기준치 아님. 실제 GPU 측정은 사용자 노트북에서 필요.

- 페이지·사진을 3D 공간의 평면(plane)으로 두고, 원근 카메라가 돌리/팬/틸트. 살짝의 원근감만으로도 "2D 슬라이드"와 "영상"의 차이가 난다.
- 얕은 심도(DOF, bokeh)로 카메라가 바라보는 사진만 선명, 주변은 흐림 → 시선 유도.
- 구현: three.js + `postprocessing` DepthOfFieldEffect. 난이도 2, GPU 중, 내보내기 결정적.
- 신문 무대는 거의 정면 카메라(약한 원근), 스트림 무대는 강한 원근.

### A2. 연속 스트림 (마블 시네마틱 인트로 느낌) — ★ 채택 (2호 무대 구현 2026-09-05)

- **판정**: 채택. `composeStream` + `StreamView`. 플레이어 무대 선택에서 "연속 스트림".
- **구현**: 사진을 굽이치는 3D 경로 옆에 좌/우/위 번갈아 배치하고 카메라 쪽으로 12~22° 돌려둠. 사진마다 정면 뷰 포즈(높이의 62%를 채우는 거리)를 만들고 그 포즈들을 CatmullRom(centripetal)으로 이어 카메라가 탄다. 머무름 1.7s, 이동 1.15s(inOutQuint로 중간 빠름). 카메라 키는 1/24s 간격 선형 샘플. 시선은 이전 사진→다음 사진으로 inOutCubic 보간. 거리 안개(near 6, far 26)는 살아있는 사진 셰이더의 `uFog`로, 먼지 900개는 시드 고정 포인트 클라우드.
- **모션 블러**: 미구현. 속도 프로필과 DOF만으로도 흐름이 읽혀 우선 보류.

- 면 구분 없음. 사진들이 곡선 경로(스플라인) 위에 띄워져 있고 카메라가 그 사이를 계속 날아간다. 지나가는 사진은 기울고 회전하며 스치고, 정면에 오는 사진은 잠깐 멈춰 살아 움직인다.
- 속도 램프(느리게 → 확 빨라짐 → 화이트 플래시 → 다음 구간), 모션 블러, 사진 가장자리 빛 새기.
- 구현: `CatmullRomCurve3`에 슬롯 배치, 카메라는 경로를 따라 lookAt 오프셋으로 진행. 모션 블러는 속도 버퍼 기반 또는 프레임 누적(내보내기용). 난이도 3, GPU 중~상.
- 사진 수가 많을 때(100장+) 신문보다 훨씬 잘 어울린다. 신문 = 정적·서사, 스트림 = 동적·몽타주.

### A3. 2.5D 깊이 시차 사진 (사진 자체가 입체로) — 보류(실험실)

- 사진에서 깊이맵을 추정 → 메시를 깊이로 변위 → 카메라가 살짝 움직이면 인물이 배경에서 떠 보인다. "살아있는 사진"의 최종형.
- 구현: transformers.js/ONNX Runtime Web으로 Depth Anything 소형 모델을 브라우저에서 실행(사진당 1~3초), 깊이 텍스처를 vertex displacement. 난이도 4, 전처리 비용 큼, 렌더는 가벼움.
- 브라우저 전용 원칙과 맞음(모델도 로컬 실행). 가장자리 늘어짐 아티팩트를 inpaint 없이 어떻게 감출지가 관건. v1.1 이후.

### A4. 반사 바닥 / 유리 테이블 — 보류

- 사진이 떠 있는 아래에 흐릿한 반사면. 스트림 무대의 프리미엄 느낌 옵션. drei `MeshReflectorMaterial`. 난이도 1, GPU 중.

## B. 재질·광학

### B1. 리퀴드 글래스 — ★ 채택 (돋보기 구현 2026-09-05)

- **판정**: 채택(제한적 사용 유지). `GlassLens` + `NewspaperStage.lenses`. 1면 헤드라인 머무름 동안 유리 돋보기가 왼쪽→오른쪽으로 훑고, 알림판에서는 위→아래로 내려간다. 눌린 구(스케일 z 0.42) + drei `MeshTransmissionMaterial`(ior 1.5, 두께 0.8r, 색수차 0.02, 왜곡 0.05, 샘플 6, 해상도 768) + 금속 테(토러스) + 손잡이. 위치·스케일·미세 흔들림은 t의 함수.
- **비용**: 투과 재질은 장면을 FBO로 한 번 더 그리므로 `LensGate`가 보이는 구간(±0.3s)에서만 마운트한다.
- **관찰**: 첫 구현에서 테를 X축으로 90° 돌려 렌즈 가운데를 가로지르는 띠로 보였다 → 렌즈 면(XY)에 놓음. 색수차 0.05는 구 가장자리에 무지개 띠가 과해 0.02로.

- 두 가지 쓰임새:
  1. **확대 렌즈**: 신문 위를 유리 돋보기가 지나가며 사진을 굴절·확대. 해리포터 신문에 딱 맞는 "장치"이자 카메라 대신 시선을 이끄는 수단.
  2. **타이틀 카드/UI 오버레이**: 제목·날짜가 반투명 유리 판 위에, 굴절·색수차·가장자리 하이라이트.
- 구현: drei `MeshTransmissionMaterial`(굴절·색수차·두께·거칠기 파라미터). 트랜스미션은 배경을 한 번 더 렌더하므로 비용 큼 → 화면에 유리 1~2개만. 난이도 2, GPU 상.
- 주의: 전면에 깔면 "아이폰 UI"처럼 보이고 종이 무드를 깨움. 포인트로만.

### B2. 필름 룩 (그레인·게이트 위브·라이트 리크·헐레이션) — ★ 채택 (실험실 부분 구현 2026-09-05)

- **판정**: 그레인(Noise, SOFT_LIGHT 0.18)과 비네트(darkness 0.55, offset 0.25)는 `/lab/camera-dof`에 함께 구현. 게이트 위브는 카메라 핸드헬드로 대체 가능해 별도 패스 불필요. 라이트 리크·헐레이션은 미구현(다음 스파이크).

- 그레인(시간에 따라 변하는 노이즈), 미세한 프레임 흔들림(gate weave), 가장자리 빛 새기, 밝은 부분 번짐(halation/bloom), 비네트, 레터박스.
- 구현: `postprocessing` 패스 조합 + 커스텀 셰이더 하나. 난이도 1, GPU 저. 모든 무대에 얕게 깔린다.

### B3. 하프톤·오프셋 인쇄 룩 — ★ 채택 (실험실 구현 2026-09-05)

- **판정**: 채택. `/lab/paper-halftone`. 종이(`paperMaterial`)와 하프톤(`halftoneMaterial`) 둘 다 텍스처 에셋 없이 셰이더만으로 구현.
- **종이 기본값**: 색 #efe4cc, 섬유 그레인 0.12, 얼룩 0.35, 접힌 자국 0.5, 비네트 0.35. 좌표는 월드 단위(uSize)라 평면 비율이 바뀌어도 왜곡 없음.
- **하프톤 기본값**: 도트 70/짧은변, 각도 45°, 강도 0.8, 잉크 번짐 0.3, 컬러 잉크 0.55, 탈색 0.3, 인쇄 대비 1.25, 종이색 #f1e8d3.
- **관찰(실패→수정)**: 첫 구현은 CMY 3중 스크린(채널별 각도)이었는데 화면 크기에서 무지개 모아레로 깨짐. 밝기 기반 **K 스크린 하나 + 사진 색을 잉크 색으로 얹는 듀오톤** 방식으로 바꾸고, 도트 반지름은 셀 중심 샘플로 결정(셀 안 균일 → 둥근 도트), 가장자리는 `fwidth` 안티앨리어싱. 그 결과 안정적. 컬러 프린지는 `misregister`로 색 잉크만 살짝 어긋나게.

- 사진 위 도트 스크린, CMYK 채널 살짝 어긋남(misregistration), 종이 텍스처 곱하기, 잉크 번짐 가장자리.
- 구현: 커스텀 프래그먼트 셰이더. 난이도 2, GPU 저.

### B4. 폴라로이드 현상 — ★ 채택(쉽고 귀여움)

- 흰 프레임에서 사진이 서서히 떠오름(화학 노이즈 → 색 → 대비). 스크랩북 무대의 기본 등장 방식. 난이도 1.

## C. 번짐·용해·변형

### C1. 잉크/수채 번짐 등장 (bleed reveal) — ★ 채택 (실험실 구현 2026-09-05)

- **판정**: 채택. `/lab/ink-reveal`, `inkRevealMaterial`. progress(0→1)는 외부에서 t의 함수로 주입 → 결정적. 세피아→컬러 전환 내장.
- **기본값**: 등장 3.0s(outCubic), 번짐 스케일 3.2, 경계 부드러움 0.08, 잉크 테두리 0.09 / 어둡기 0.55, 위→아래 편향 0.35.
- **관찰**: 스크럽 0.4s 시점에 세피아 구름이 종이에 스며드는 모양이 좋다. 잉크 테두리 밴드는 기본값에서 미묘함 → 신문 무대에서는 0.12~0.15 권장. 고급형(확산 시뮬)은 아직 필요 없어 보류.

- 사진이 종이에 잉크가 스며들듯 나타남. 노이즈 마스크의 임계값을 시간에 따라 낮추고, 경계에 어두운 잉크 테두리 + 블러.
- 구현: 노이즈 텍스처(FBM) + threshold + edge darken 셰이더. 난이도 1~2, 결정적.
- 고급형: 핑퐁 FBO로 확산(diffusion) 시뮬 → 진짜 번지는 느낌. 상태 있음(내보내기 순차 시뮬). 난이도 3.

### C2. 파티클 분해·재조합 — ★ 채택 (신문 무대 구현 2026-09-05)

- **판정**: 채택. `ParticleTransitionMesh` + `NewspaperStage.transitions`. 면이 넘어갈 때 앞 면 마지막 사진이 22,000개 입자로 흩어져 카메라 이동을 따라 날아가 다음 면 첫 사진 자리에 모인다. 출발 사진은 `Slot.vanish`로 사라지고 도착 사진은 입자가 모이는 순간 페이드 인.
- **구현**: 두 슬롯의 같은 격자 칸을 잇는 (uvA, uvB, seed) 속성만 두고, 위치·색은 정점 셰이더에서 progress로 계산(2차 베지어, 시드로 흩어진 중간 제어점, 왼쪽·아래부터 출발하는 지연). 색은 A 텍스처 → B 텍스처로 비행 중간에 전환. 순수 t 함수라 내보내기에서도 동일.
- **관찰**: 카메라 쪽(+z)으로 튀는 입자가 큰 원반으로 보여 z 흩어짐을 줄이고 점 크기에 상한(18px)을 둠. 22k 입자는 SwiftShader에서도 부담 없음.

- 사진이 수만 개 입자로 흩어져 날리다가 다음 사진으로 모인다. 해리포터 무드의 "마법"을 가장 직접적으로 준다.
- 구현: GPU 포인트(instanced), 각 입자에 (uvA, uvB) 두 좌표, 커브 노이즈로 중간 경로, t로 보간. 난이도 3, GPU 중. 결정적으로 설계 가능(입자 경로가 t의 함수).

### C3. 액체/디스플레이스먼트 트랜지션 — ★ 채택

- 두 사진 사이를 왜곡 텍스처로 녹이듯 전환. `gl-transitions` 카탈로그(수십 종, MIT)에서 종이·잉크·물결 계열만 골라 쓴다. 난이도 1.

### C4. 종이 물리 (페이지 컬·접힘) — ★ 채택 (신문 무대 구현 2026-09-05)

- **판정**: 채택. `CurlSheet` + `NewspaperStage.sheets`. 활자와 사진이 별도 메시라 지면 자체를 구부리면 활자가 떠 보이므로, **다음 면을 덮은 백지 한 장**이 카메라 도착 전후(−0.7s ~ +0.55s)에 모서리(홀수 면 우상, 짝수 면 우하)부터 대각선으로 말리며 벗겨지는 방식. 밑의 인쇄면은 그대로 두고 벗겨지는 종이만 변형한다.
- **구현**: 48×64 분할 평면. 정점 셰이더가 모서리에서 대각선으로 진행하는 축을 기준으로, 축을 넘은 깊이 s를 반지름 R(0.55) 원통에 감는다(각 s/R, π를 넘으면 뒤집혀 눕는다). 프래그먼트는 종이 섬유 + 희미한 뒷면 인쇄 비침, 뒷면은 어둡게, 감긴 부분에 음영. progress는 t의 함수(inOutCubic).
- **관찰**: 파티클 전환(C2)과 같은 구간에 겹치므로 입자가 착지할 때 백지가 거의 벗겨져 있도록 t0를 도착 0.7s 전으로 잡았다.

- 페이지가 원통을 따라 말리며 넘어감. 정점을 원통에 감는 vertex shader. 그림자 포함. 난이도 2~3.

### C5. GPU 유체 시뮬레이션 — 보류(실험실)

- 배경으로 흐르는 잉크/물 유체, 사진이 그 위에 떠 있거나 유체가 사진을 드러냄. Navier-Stokes 핑퐁 FBO. 난이도 4, GPU 상, 상태 있음.
- 임팩트 크지만 무드 통제가 어렵다(쉽게 "테크 데모"처럼 보임). 스트림 무대 오프닝 한 번 정도.

## H. 레이아웃·순차 교체 (사용자 피드백 2026-09-06)

## I. 실사 포토북 (사용자 피드백 2026-09-06, 참고: 테이블 위 레이플랫 앨범 사진)

### I1. 물리 기반 책 모델링 + 조명 — ★ 채택 (구현 2026-09-06)

- **판정**: 채택. 지금까지의 무대는 셰이더로 그린 평면(비조명)이었지만, 포토북은 실물처럼 보여야 하므로 PBR 재질 + 방향광 그림자 + 환경광으로 간다. 테이블(z=0) 위에 하드커버 앨범: 뒤표지·책등·앞표지(RoundedBox, 패브릭 재질: sheen + 노이즈 범프), 페이지 블록(단면 줄무늬 텍스처 박스, 넘김에 따라 높이 변화), 잎(leaf) 평면. 사진은 인화지 재질(clearcoat 0.3)로 페이지에 인쇄된 것처럼 붙는다. 켄번즈 없음 — 카메라가 움직인다(전체 → 근접 1~2장 → 넘김).
- **잎 굽힘**: `pageBend.ts`. 잎에 붙은 모든 메시(종이 앞·뒷면, 사진)의 정점을 잎 공간에서 같은 함수로 변형한다. 책등 거리 u에 각도가 선형(θ = α + β·u/W, β = -bow·sin α)이라 원호 적분이 닫힌 형태로 풀린다 → 결정적, 정점 셰이더 1개. 그림자용 깊이 재질도 같은 굽힘을 써서 넘어가는 잎이 페이지에 그림자를 드리운다. `uInvModel`로 메시별 역행렬을 넘겨 어떤 계층에 있어도 잎 공간으로 돌아온다.
- **관찰 1**: 페이지를 양면(DoubleSide) 평면 하나로 만들면 왼쪽 페이지(α=π)에서 정점 법선이 아래를 향해 그림자 normalBias가 거꾸로 걸리고, 페이지가 자기 그림자(회색 격자 acne)를 받는다. → 앞면·뒷면 단면 평면 둘로 분리(실제 종이처럼). 해결.
- **관찰 2**: 활자(troika)는 굽히지 않으므로 잎 그룹 밖에 두고 펼쳐진 상태의 월드 위치(높이 포함)에 놓으며, 넘김 중에는 숨긴다.
- **관찰 3**: 후처리(EffectComposer)가 렌더러 톤매핑을 끄므로 조명 무대에만 ACES 톤매핑 패스를 넣는다. DOF는 카메라 시선점에 초점(focusRange 1.1, bokeh 2.6)으로 참고 사진의 얕은 심도를 낸다.
- **소품**: 커피잔(Lathe 프로필 + 받침 + 토러스 손잡이, 세라믹 clearcoat), 낱장 인화지 2장(흰 테두리 박스 + 사진). 모두 테이블 위 책 바깥, 심도 밖에서 흐릿하게. 다음 후보: 드라이플라워, 리넨 천, 창가 빛 무늬(고보).

### I2. 샷 기반 연출 + CG 룩 마감 — ★ 채택 (구현 2026-09-06, 피드백: 넘김 대신 컷, "실제 CG 작업 수준")

- **판정**: 페이지 넘김을 버리고 **짜인 구도의 샷**을 컷으로 잇는다. 제품 사진 구도 프리셋 5종: 3/4 위(참고 사진 구도), 플랫레이(정수리), 디테일(사진 1장 근접·얕은 심도), 그레이징(낮게 스치는 앵글), 페이지 포커스(한 페이지). 스프레드마다 도입 1 + 디테일 1~2 + 마무리 1. 샷마다 카메라가 천천히 밀고 들어가거나 옆으로 흐른다. 스프레드가 바뀌는 컷에는 라이트리크 플래시. 첫 샷은 닫힌 책 → 표지 열림 → 3/4 뷰로 이어지는 한 샷(컷 없음).

- **재질**: 표지는 절차적 리넨 직조 노멀맵(평직 sin 패턴 + 노이즈), 종이는 미세 섬유 노멀맵, 사진은 인화지 clearcoat. 캔버스로 만들어 네트워크 의존 없음.
- **후처리**: N8AO(접촉 음영), 샷별 DOF(초점 거리·보케 크기), 약한 블룸, 미세 색수차, 그레인, 비네팅. 핸드헬드 미세 흔들림(무리수 비 사인파 합, t의 함수)이 카메라에 얹힌다.

- **관찰 2**: 스포트라이트 `map`은 RGB만 쓴다. 창살을 알파로 뚫으면 흰색으로 남으니 검게 칠해야 한다. 그림자 카메라 fov는 angle에서 자동 계산되므로 손대지 않는다.
- **관찰 3**: 노출은 스포트 강도 36(candela, decay 1.2) 근처가 적정. 70이면 종이가 날아가고 창살이 안 보인다.

## 실험실(`/lab`) 운영 방식

- 앱 안에 `/lab/:device` 라우트. 장치마다 독립 씬 + `leva` 슬라이더로 파라미터 실시간 조정.
- 스파이크 예산 0.5~1일. 끝나면 이 문서의 해당 항목에 **판정(채택/보류/폐기)·스크린샷·GPU 측정치·남긴 파라미터 기본값**을 기록.
- 채택된 장치는 `features/renderer/devices/`로 이동해 무대 템플릿이 조합해 쓴다. 장치 = 재사용 가능한 컴포넌트/패스 단위.
